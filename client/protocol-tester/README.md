# 本地协议测试器

独立 Windows EXE，不需要启动游戏客户端。通过既有 TLS 认证、SDK 登录、角色加载和大厅切换流程连接本地测试服，不增加服务端调试接口。

## 使用

1. 启动本地服务器，再打开 `dist/协议测试器/功夫小子协议测试器.exe`。
2. 选择本地登录器的 `bridge.json`，输入没有在游戏中登录的测试账号，点击「连接 / 保存账号」。
3. 在中间的用例下拉框选择资料、登录、商城、装备、房间、战斗、结算等项目，填写下面的参数，点击「执行此项」。「生成 HEX」只预览，不发包。
4. 列表显示收发包、字节数及回包耗时；商品会显示商品键和价格，库存显示实例号，结算显示经验金币。选中一行可查看完整 HEX。默认8秒超时，全员输入/结算/加载超时观察允许等100秒；预期填0表示只发包、不检查响应。「取消等待」不撤销已经发出的操作。
5. 需要另一位玩家时点「新增测试账号窗口」，用另一个账号登录。同一账号不能在游戏和测试器同时使用。每个窗口维护自己的连接、房号和战斗序号。

## 双账号房间、战斗测试

新增「房间 / 移交房主」：A建房、B加入后，A填写B的UID执行；房号从当前会话自动读取。两边应收到3160新房主，A收到4052成功，准备状态清除。随后A再移交应被拒绝，B可以把房主移交回A。该入口使用4051/12B，不复用踢人3140。

1. A 建房（地图0为服务器选图），记下状态栏/房间列表的房号；B 加入该房。可先测试密码错误、换队、修改设置、踢人及重新加入。
2. B 准备，然后 A 点「准备或房主开始」。两边收到4080后显示“加载”。
3. 两边分别点「资源加载完成」，收到4180后分别点「输入就绪」。全员完成才收到8070进入“战斗”。
4. BUFF/技能/事件重放从一边发，在另一边观察8071。持续时间3000表示毫秒；序号自行递增，同内容同序号可测试去重。事件重放只改已确认的发送身份与上下文，目标等其余字段仍需匹配当前房间。
5. 两边在「上报胜负平及奖励」填写相同的成员HP清单，例如 `10009:0,10010:100`。收到4120后查看实际经验、金币和2160掉落，再分别点击「回房与关闭查看结果」。重复报告可检查是否重复发奖；每次新的购买点击则是一次新购买，不能用它证明购买幂等。
6. 要测加载超时，开局后故意不点资源或输入就绪，选「等待加载超时」观察约90秒的3115→3100回房；测试器不伪造超时。房主在加载/战斗中离房可验证另一方保留房间和3160房主转移。

购买、装备和结算会实际改变独立测试库中的账号数据。奖励/掉落规则仍在GM配置，本工具只走真实协议验证发放；不会修改线上配置。

## 清单覆盖及未实现项

以 `protocol/ImplementationBacklog.md` 为索引，已确认请求提供参数化测试；推荐/优惠保留暂缓说明。荣誉挑战战绩支持目标UID及历史期查询，服务端须显式配置累计规则，赠送会实际扣点券投递单件邮件，收件人用邮件列表/详情/领取验收，21410在服务器配置weapon_levels后返回21411；未配置只返回提示，等待21411仍会超时。21412仅在显式启用weapon_upgrade_mode=consume_score_keep_level后开放，按自定义规则实际消耗金币与熟练度，失败保留等级；每次点击是新尝试。

创建角色、宠物/法宝完整闭环、称号、到期调度、指定移交/观战/锁位的关键字段或服务端实现仍不完整，提供对应缺口说明，不构造虚假成功包。到期/新增/更新等服务端通知在收包日志观察，不能反向冒充客户端请求。字段已知的战斗事件支持原包重放，未知子命令被服务器忽略也不应标成通过。

断线后默认每 15 秒重新认证进入大厅，无需打开游戏。错误密码或配置校验不一致时停止重试，修正后再连接。重连不自动重放上一次请求，避免重复执行有副作用的协议。

账号密码由 Windows 当前用户加密保存在 `settings.bin`。日志写入 EXE 旁的 `logs`，不记录认证密码和摘要。首次运行自动提取内嵌组件到 `components`。本版本仅允许本地 TLS 目标。

收到预期协议只证明回包号匹配。资料回包另显示长度校验及目标 UID；P2P 注册与续期用于真实进房前置条件，不模拟客户端渲染世界。游戏界面、动作、物理、BUFF自然到期仍需真实客户端验证；不能用转发成功证明冰冻常驻已经修复。

收到武器升级配置21411时，日志逐条解码等级、熟练度阈值、金币费用、显示成功率、攻击加成原值，并保留未知字节16。长度错误、零进度分母、重复等级和索引不一致会提示风险。服务器升级配置及升级事务仍待实现；测试器不会合成配置注入游戏。

## 构建

在 `server/go-server` 目录：

```sh
go build -trimpath -o ../../dist/tester-components/ProtocolTesterCore.exe ./cmd/protocol-tester
```

在仓库根目录的 Windows 构建环境：

```sh
dotnet publish client/protocol-tester/ProtocolTester.csproj -c Release -o dist/协议测试器
```

Go 协议组件复用服务端现有编码器；WinForms 只负责界面、账号加密保存、自动重连和日志。对外入口仍为一个 EXE。

可选验收：设置环境变量 `OPENKFO_TEST_PASSWORD` 后运行 EXE 的 `--scenario-test` 参数。它使用 localtest9/localtest10，实际创建临时房间、结算一局并等待90秒加载超时，约两分钟完成；输出 `scenario-test.json` 和本地日志。它会改变这两个测试账号的结算数据，请确保账号未在游戏中使用。`--self-test` 保留原有只读查询及连接组件中断重连检查。

## 完整协议链自动回归

设置环境变量 `OPENKFO_TEST_PASSWORD`，在测试器目录运行：

```text
功夫小子协议测试器.exe --protocol-regression
```

使用空闲的localtest8/9/10和现有本地配置，自动测试自己/他人资料及21000、20360后续查询，开战8090计时门，BUFF添加、来源清零的远端删除及去重，三局胜负平结算与回房，房主断开、房间保留、重新连接。不购买商品、不要求商城余额；结算仍会改变测试账号经验金币。结果写入`protocol-regression.json`，失败记录阶段与原因。该命令验证真实服务器协议链，不模拟客户端渲染与自然到期算法；旧回归中的20370仅验证包长度；荣誉历史查询和累计由新增独立库测试另行覆盖，尚不证明原生UI分级显示。

### 无角色账号

连接前可填写“无角色时创建昵称”。仅当服务器下发1125候选时，测试器按服务器提供的完整七槽选项发送1150，再进入正常大厅链；已有角色不会覆盖。留空则不创建角色。昵称随本地设置加密保存。服务器必须配置character_choices，测试器不会自行赠送未下发的装备。

### 多频道

连接前填写频道ID（默认1），与账号一起保存。必须是服务器lobby_ids中配置的ID；连接期间禁用编辑，断开后可改频道再连。Go核心同时支持连接JSON中的lobby_id。原生同连接切换链由TestCharacterCreationTLS自动验证，不需要玩家点击；该测试只允许openkfo_debug_独立数据库，并创建/清理临时账号，不使用现有玩家账号。
# 房间交换座位

用例菜单支持3260申请、3262同意、3263拒绝。申请自动写入本人UID，座位使用0–7；目标UID为0表示空座位。有人的座位须由对方测试窗口收到3261后同意，双方收到3265才表示成功。此操作不是移交房主。

同意/拒绝使用最近收到的24字节3261原文；撤销、交换成功、离房、重登或重新进房会清除旧请求。日志解析显示双方64位UID和原/目标座位，3264表示拒绝或撤销，3267表示忙碌。服务器自动测试覆盖同意、拒绝、过期、重复回复和房间状态变化后的失效，不依赖原生客户端点击；此证据不代替游戏画面验收。


### 法宝自动网络回归（开发验证）

设置 `OPENKFO_DEBUG_DSN` 为独立测试数据库连接后，在 `server/go-server` 运行：

```sh
go test ./cmd/protocol-tester -run '^TestTalismanTLS$' -count=1
```

用例拒绝非 `openkfo_debug_` 数据库，使用临时账号和本机TLS监听器自动完成双人登录、建房、开战、法宝主动/被动使用、重复事件、额度耗尽和离房。清理临时账号及道具回执；测试库战局序号会正常递增。无DSN时跳过，不将跳过视为网络验证通过。不得把凭据写入源码或提交。该测试不证明原生客户端的动画及效果表现。

该完整战斗用例同时运行`object-events-9000`和`object-events-9500`子测试，自动模拟申请者及控制者，检查申请/接受/拒绝/取消/完成、重复请求/回复、错误对象键、伪造控制者、9000错误战局和控制者本机完成路径。它使用合成对象键验证协议隔离与流程，不证明客户端地图中真实存在该物件；测试器不会为玩家凭空创建场景物件。
# 开发验证：原客户端关卡目录

### 基础任务自动网络验收

设置独立测试库环境变量 `OPENKFO_DEBUG_DSN` 后，从 `server/go-server` 运行：

```sh
go test ./cmd/protocol-tester -run '^TestTasksTLS$' -count=1
```

用例在连接前拒绝非 `openkfo_debug_` 数据库，创建两个临时账号，通过真实TLS登录、P2P、建房和加载，连续两局互换胜负，发送战报并返回房间。第一局任务保持进行中，第二局查询才发奖；检查重复战报不增加统计、每人两次参赛一次胜利、重复查询不重复奖励，以及注销重连后恢复任务和余额。配置及结算回执使用连接级临时表，正常分配独立测试库的战斗序号，结束清理临时账号及任务回执。不使用现有玩家或直接修改统计值；不证明原生任务弹窗、其他任务类别或战斗画面。无DSN时明确跳过。

从Go模块目录运行`go test ./internal/desktop -run '^TestStageCatalogue' -count=1 -v`。设置环境变量`OPENKFO_CLIENT_ARCHIVE`为自行取得的`config.spf2`绝对路径后，会执行真实资源读取并确认文件哈希未变化；不设置时只运行合成XML测试，资源测试明确跳过。当前资源实测读出50条地图选择记录。这不代表21370服务器关卡业务已经实现。
