# 宠物与法宝：类型和装备入口

## 使用槽位与收包顺序核实

slot-use.asm绑定当前PE哈希，完整保存9DE410、9F94B0、9F9560、99A750。9DE410将参数37/38分别映射第一/第二法宝，再调用99AB90；9F94B0分别push 0x25/0x26后调用99AE70。因此8291/8292的+39确定为装备槽37/38，不是0/1索引。9F9560同样按37/38选对象。

99AB90/99AE70先发8071事件，再发4201；不能复用药水4200先登记意图的顺序。+43..58未见发送函数初始化，不应当作费用、身份或稳定去重依据。主动使用99A750还检查MP、模式与角色状态，尚未证明服务端只检查额度即可完整兼容。

新增protocol.ParseTalismanEvent用于解析75B、事件号、槽位、64位身份、事件序号和房间上下文；Match对认证身份及当前房间做匹配。测试器使用该解析，旧测试样例的选择值2已纠正为槽38。服务器尚未开放这两类事件消费，持久化扣除、事件与4201配对、4206/4207回包继续待补。


## 库存额度与修理事务

当前99AA80构造函数（inventory-quota.asm）读取库存+0为对象+8，证明4201/4206的物品键是实例ID；从库存+5查物品配置；99AB0E读取库存+23的uint16，除100写对象+170。因此剩余额度沿用现有库存记录，不新增另一份余额。最大额度另从商品查找结果取得，尚未恢复官方修理规则。

新增Store.RepairTalisman与显式TalismanRepairRule（item/material/quantity/capacity），规则不冒充原版。账号行锁内验证本人type30实例、状态、期限及未满额度，再扣本人有效未装备type60材料，允许跨堆叠，清零堆叠删除，更新+23额度并保存talisman_repairs操作回执，全部同事务。重放返回当前额度，不补回后续消耗；同操作换材料/数量/上限拒绝。

TestTalismanEquipmentLocalDatabase扩展后实际通过（19.743s）：双槽共存、同槽替换、卸下；跨堆叠修理、重复不扣、使用后重试不再补满、材料不足、参数篡改、跨账号拒绝。临时账户/库存/修理回执清理，辅助SSH关闭。报价/修理网络入口尚未接入，未宣称原生UI或TLS修理通过。

## 使用额度回包与第二槽

replies.asm保存完整当前PE消费者。4206注册到A28290，严格12B：+0与法宝对象+8匹配，+4无符号DWORD经99A620除以100写入对象+170并刷新显示，+8非零触发警告路径。A28290分别获取第一/第二法宝，并向99A620传槽37/38，因此服务器增加type30的第二允许槽38；没有扩大slot0默认规则。

4203经826870到874600，拷贝32B到修理窗口+578。+4和+8分别查物品配置用于物品/材料图标；+16传数量格式化器；+20/+24各除100形成当前/最大额度显示；+28控制修理说明。4204原先+4来自UI+580，实际对应报价+8材料配置，不能当金币报价。+12未确认，保留未知。4205由826450读取+4错误码，0为成功；非零直接索引文案表，不能随意填错误码。4207读取+4物品配置，+0交给不足提示窗口作为后续修理键。

测试器增加4203/4205/4206/4207边界和字段诊断；第二槽代码已加入，存储测试扩充为双槽共存，但本次普通测试无DSN时跳过，不能称第二槽已通过独立库实测。完整修理材料扣除/额度持久化仍待实现。

## 主动/被动使用及修理协议恢复

枚举注册7A3177起的double常量BE9440..BE9410分别为4201使用、4202修理报价请求、4203报价响应、4204修理请求、4205修理响应、4206使用响应、4207不足通知。7A4577/7A4593分别注册8291装备被动使用、8292主动使用。仅名称/编号不能推断回包字段。

当前PE完整发送函数见use-repair.asm：99AB90主动使用发送8071/8292（75B）后4201（8B）；99AE70被动使用发送8291（75B）后4201（8B）。事件+39为函数参数选择值，+59为401000取得的实体UID，+67起为432440返回的8字节房间上下文；+43..58未解。4201首DWORD来自法宝对象+8，需进一步证实实例/配置键语义；主动第二DWORD来自配置对象+4乘100后截断，被动函数没有对第二DWORD明确赋值，严禁直接相信其报价扣费。

873F30发送4202/4（UI+5D4）；874360发送4204/12，前两个DWORD来自UI+578/+580，末DWORD初始化0。修理报价、成功回执和剩余额度字段仍需追消费者，不构造成功或直接扣金币。

测试器已增加这些已确认形状的诊断、错长检查与64位UID测试；未开放8291/8292服务器透传或消耗扣费。cmd/protocol-tester测试通过（0.550s）。

当前客户端config.spf2的item.txt中type30同时包含法宝与宠物，例如303002生命护符、303110爱爱、303111恋恋、303117雪人。talisman.xml按这些物品ID配置装备被动状态、主动状态、持续值、ActiveCost、ActiveCostSKillpt和EquipCostPerBattle；尚未追完每项在客户端的消费，不能把名称直接当服务器扣费单位。fairy.xml负责跟随特效物体，不是服务器宠物背包协议。

当前PE证据见warehouse-slot.asm（含文件SHA256）。8B3890仓库装备动作在8B3919比较类型0x1E，在8B3924写UI+630=0x25（槽37），8B3CC3调用8A9700现有2080发送器。区别于660CE0的默认槽函数，type30在此明确指定槽37，未证明其slot0语义。
