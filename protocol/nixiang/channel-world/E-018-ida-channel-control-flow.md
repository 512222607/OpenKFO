## 地址基准修正

旧报告使用 `0x10000` image base；当前 IDB 使用 `0x0`。因此旧地址需减 `0x10000`，例如旧 `0x910510` 对应当前 `0x900510`。本证据中的地址全部使用当前 IDB 基准。

## 已确认的链路

1. `0x8FE7B0 RoleSelectionUI_Send3320` 是角色选择 UI 处理器，点击角色后发送 `3320/4`（角色 ID）。
2. 状态 5 注册表把 `3330` 分派到 `0x8136E0 Handle_RoleSelectAccepted_3330`。该处理器设置当前角色并刷新角色/玩家子系统，不发起频道连接。
3. 同一注册表把 `1201` 分派到 `0x812F00 Handle_ChannelAdvance_1201`。处理器要求至少一个 DWORD；载荷值为零时调用 `0x8F7870 Advance_SelectedChannel`。
4. `0x8F7870` 读取 UI 对象 `+1412` 的频道索引和 `+1416` 的分组，调用 `0x900C00 Connect_SelectedChannel_2010`。
5. `0x900C00` 从已装载的频道记录中解析地址、端口和两个服务器标识，最终调用 `0x900510 GameServer_ConnectAndSendLogin(..., 1)`。
6. `0x900510` 新建连接、构造固定 96 字节登录结构；末参数非零时发送 `2010/96`，否则发送 `1010/96`。
7. `0x8F95E0 Scan_SelectedChannel_ThenAdvance` 扫描两组各 30 个频道控件，把选中索引写入 `+1412/+1416`，随后进入上述推进路径。

## 2030 动态验证补充（2026-09-07）

- `2030 -> 0x813160 Handle_AlternateLoginResponse_2030`，载荷必须恰好 52 字节。
- 已验证结构为：首 DWORD 世界 ID，`+4` 起 20 字节 NUL 终止 ASCII 主机名，`+24` 为 uint16 端口，`+26` 为 DWORD route ID，其余尾部清零。
- 实验值为世界 ID `1001`、`127.0.0.1`、端口 `5136`、route ID `1`。Frida 记录到 `2030/52`，随后客户端进入“频道：本地测试服”的大厅，并建立到 5136 的 TCP 连接。
- 因此 2030 已从候选升级为真实客户端动态验证；任意全零 52 字节仍不是有效响应。

## 本轮判断

旧 v4 在真实角色点击后只回 `3330`，因此停在角色/频道界面与静态控制流一致。`3330/4 -> 1201/4(0) -> 2010/96 -> 2030/52` 已完整动态验证。当前下一边界已推进到 5136：TCP 建连成功，但 P2P 应用层未完成连接，创建房间在客户端本地被拦截。
