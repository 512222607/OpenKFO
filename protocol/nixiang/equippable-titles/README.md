# 可装备称号与成长称号核实

2026-09-19，只读检查；没有修改业务代码、客户端或运行服务。

## 两套数据

- 成长称号：roletitle.xml，角色360B档案+123，一字节等级；4125通知、4126选择附带奖励。天赋少年Ⅰ是2。它不代表全部称号。
- 可装备称号：item.txt类型31，完整物品ID，如313101天下第一、313111弑神者、313203武器大师。配置同时包含Animation/TitleAnm展示图与Picture/ItemIcon背包图。应复用库存实例与物品发放，不写入档案+123，也不拿4125当物品发放协议。

## 版本核对

client/config.spf2有47条类型31；client/Data/config.spf2有48条，另含313312。两者313111描述也不同。本文catalogue.json采用GM读取的Data/config.spf2，不能把47说成当前所有配置包的统一数量。

## 装备证据与边界

当前gfld.dat的660CE0默认装备位置switch，type31跳660D5E，返回0x2A=42，证据native-default-slot.asm。仓库8B3919附近对其他特例处理后从选择项+10取槽位。可以确认类型31存在原生装备位置；尚未逐条证明该类型全部显式可选槽位，也未证明同一角色能同时显示多个类型31。

多个独立称号可用多条inventory实例表示；拥有多个与同时佩戴多个必须区分，不应据单个默认槽42硬编码结论“最多一个”，也不应任意新增43/44等位置。

## 当前服务器缺口及实现方向

- persistence/store.go Slots没有31，defaultEquipmentSlot也未接31；当前可发库存不等于可装备。
- 应扩展现有物品装备/卸下流程（2080/2090、2300及1120库存同步），核对类型31实际发包槽位与显示记录，而不是新建平行称号背包。尚无类型31整链实机验证。
- 成长称号授予与称号物品奖励分开；上层奖励业务可同时调用成长称号服务和库存发奖事务。防重复、所有权、期限、同槽替换以及重登恢复应复用现有物品规则。
- 后续编码前尚需明确“同时多称号”在当前版本的UI及各槽映射；不能以成长称号与装饰称号可并存替代这一事实核实。
