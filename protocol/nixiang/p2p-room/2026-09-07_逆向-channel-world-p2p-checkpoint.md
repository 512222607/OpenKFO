## 结论摘要

真实隔离客户端已经从既有角色 `t07` 完成频道选择、世界交接并进入游戏大厅。关键链路是：

```text
角色选择 3320/4
  -> 服务端 1201/4(0)
  -> 客户端 2010/96
  -> 服务端 2030/52(world=1001, host=127.0.0.1, port=5136, route=1)
  -> 大厅初始化请求簇 + 5136 TCP connect
  -> 显示“频道：本地测试服”大厅
```

创建竞技房间并选择团体战后，客户端弹出“还没有连接P2PServer, 无法加入房间”。线日志中 5136 仅出现 TCP 连接，没有客户端应用层首包，也没有 10035 创建房间消息。因此本轮未恢复房间协议；当前缺口是 5136 上由 `SDP2P.dll` 实现的应用层握手或连接确认。

## Findings

### F-021：非零频道记录与 1201(0) 可稳定推进到 2010

- 证据：E-039、IDA `0x812F00 -> 0x8F7870 -> 0x900C00 -> 0x900510`
- 结论：频道列表记录 ID 必须非零；group 0 / slot 0 的有效记录配合 `1201/4(0)` 会触发模式 1 的 `2010/96` 登录。
- 置信度：高，静态与动态交叉验证。

### F-022：2030/52 是进入大厅的世界/P2P 端点交接结构

- 证据：E-040、E-041、IDA `0x813160`
- 结论：52 字节结构的世界 ID、主机、端口和 route ID 足以让客户端进入大厅并连接 5136。
- 置信度：高，真实客户端动态验证。

### F-023：当前房间失败是 P2P 应用层未就绪，不是团体战参数错误

- 证据：E-042、E-043、5136 线日志
- 结论：客户端在发送创建房间请求前检查 P2P 连接状态；当前 TCP connect 不等于 P2P 已连接。5136 服务端没有发送 SDK 期待的握手/确认，故客户端本地拦截。
- 置信度：高。首包格式及具体状态机仍未知。
