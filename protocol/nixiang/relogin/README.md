## P2P 注册跨重登恢复（2026-09-18）

真实断线证据：23:08:42 新登录 UID 已认证、进入大厅，1156/12 仍携带旧 P2P 1001，中间没有新 1001 注册。旧实现清零 P2P，因此拒绝 1156。参考同目录 native-2070.asm 和 ../p2p-room/2026-09-07_逆向-sdp2p-udp-login-report.md：GS 登出与 SDP2P UDP 注册是不同生命周期。

实现：1001/1002 注册成功时，服务器在加密隧道的 UDP 包外层附带 HMAC 签名的 peer_receipt，原生 UDP 字节不变。Bridge 按 PID、进程创建时间和映像保存到内存，下次密码认证时附带凭据。服务器在密码验证后验证签名，拒绝恢复正在被其他会话使用的编号，只恢复 P2P 注册，不恢复账号、房间、背包缓存、游戏通道和 Bound。不再使用按账号缓存一分钟的候选实现。

SDK 初始化保留运输层 P2P 编号与 UDP 端口，清理游戏状态。1001/1013 可以在游戏通道建立前到达；1156 仍须匹配当前认证 UID 和已注册 P2P 编号，并续期运输层租约。战斗转发仍要求 Bound、UDP 端口、有效租约及同房间成员。恢复凭据不能替代账号密码，不写配置文件和日志。

边界：凭据只对当前服务器运行实例有效；重启服务器后需要退出旧游戏进程再启动，以重新注册原生 P2P。Bridge 进程退出也会清空内存凭据。首次升级应使用新登录器启动游戏一次，之后普通重登不重启游戏。
