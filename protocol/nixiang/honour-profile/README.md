请求20360恰12字节：+0目标UID qword，+8为窗体+754索引。883EA0查询当前值；887150加1，8871C0减1。886EF0与全局频道/世界对象（4164E0）的+18C首DWORD比较，索引1与全局上限分别控制按钮。88900C将这个全局值拷入窗体+754作为初值。上限结构57字节的服务端来源尚未闭合，不能直接宣称+8是日期或任意页码。

当前服务器20370首DWORD=0，因此后面的英文未配置文字实际上不会显示；客户端清空页面。测试器已纠正说明并增加目标/历史页参数及字段诊断。接下来需恢复57字节目录的下发来源、挑战对局认定和荣誉累计规则，再接持久化；不把普通经验或全部胜场假填成荣誉数据。

## 历史目录来源已闭合

1035注册处理器A2B930（AF2669写handler；opcode=0x40B），严格要求57字节，调用4164E0取世界管理器，再由41BEB0复制57字节至+18C。4F4570返回同一区域；RoleInfo用首DWORD初始化历史选择和翻页上限。其他消费者9032FB/90335C/9033F4会复制该结构，8FA390只读取首DWORD并按本地匹配配置查询。其余53字节完整业务语义仍未恢复。

Bootstrap补发1035/57，首DWORD=1表示本服初始化单期目录，其他字段零。这不启用挑战赛、不制造玩家战绩，20370仍为空记录。1035在频道目录和角色资料前发送，避免RoleInfo依赖未初始化历史选择。协议编码测试及现有传输登录顺序测试同步；原生UI尚未验证。以后多期服务必须配置和持久化对应真实历史，不能只增大首DWORD。

## 本服可选累计与查询

服务器honour配置示例（自定义规则，不代表原版）：

```json
"honour": {
  "periods": ["本服第一期"],
  "modes": [1],
  "win_points": 10,
  "loss_points": 2,
  "draw_points": 3
}
```

期号为名称数组下标+1；新期追加名称，不重排历史。当前期是最后一期，1035首DWORD与其一致。模式按已有房间模式字段显式选取；无modes不累计，训练模式5、少于两人、不一致战报不累计。未配置时保持空记录。描述限制200字节且GBK往返可编码，无控制字符。

确认结算在同一数据库事务增加honour_stats，现有battle_settlements回执保证重复结算不重复增加；失败回滚同时覆盖奖励和统计。按期按玩家隔离；排名以荣誉值降序，共同分数同名次。计数和积分封顶INT32_MAX以匹配原生有符号显示。

20360按目标UID和期号读取，20370填荣誉排名/值、挑战场次/胜场与期名。未知、不存在或越界历史返回37字节空记录以清掉旧页。原始包+4..15尚无确定语义，保留零。完整原版挑战匹配仍未实现。

## 可配置荣誉分级

当前客户端存在BattleLevel00.png至BattleLevel010.png共11个图标，+24允许本服等级0–10。honour可增加`"level_points":[100,300,500]`：积分不足100为0，达到100/300/500分别为1/2/3。最多10个严格递增阈值，各值不超过INT32_MAX；非空分级表必须同时配置期目录。未配置时仍为0，不用人物等级代替。

这是显式自定义规则，示例数值不是原版曲线。当前全部历史期使用同一张阈值表，在查询时计算等级；修改阈值会改变历史页面的等级显示，但不会改写已累计的积分、场次或胜场。需要冻结各期等级时应先扩展按期规则，不能把当前表当成历史快照。未自动启用运行配置。
