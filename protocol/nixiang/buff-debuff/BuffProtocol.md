# BUFF / DEBUFF 协议

更新：2026-09-18。范围：当前客户端的 8071/8126/8150、效果生命周期，以及凌云神腕 X 冰冻复现。此文补充字段和调用链，不表示常驻问题已经修复。

## 1. 证据与结论

静态对象为本机 `gfld.dat`，SHA-256 `98c43be72ac7600b368d4e185d75205376f79e938ea42e4b16ce8f8c4bae827b`，PE ImageBase=`0x400000`。下列地址直接对应本二进制；不直接复用旧运行时镜像地址。

- [二进制元数据](evidence/binary.json)：导入表、计时换算常量、哈希。
- [8150 处理器](evidence/0082C6E0-8150_receive.asm)：完整入口至返回指令。
- [8126 处理器](evidence/0082B8D0-8126_receive.asm)：查技能效果表、构造 8150。
- [本次实包](evidence/battle-sample.json)：15:32:58 的四条上行及四条服务端排队下行。

**3000 是毫秒持续值，正常时钟下约 3 秒，不是 3000 秒。** 添加时会先按特定修正系数调整，再加到当前战斗时钟，得到绝对到期值。自动移除还需要实体门控和更新函数执行，不能只看持续值。

## 2. 收发总链

```text
客户端技能命中
  → 8071 子命令 8126（查技能属性效果列表）
  → 满足目标/效果准入条件时逐条构造 8150
  → 8150 op=1：效果容器添加/更新，计算到期时刻
  → 当前 Go 服务校验信封、房间和身份后转发给其他成员
  → 接收客户端 82C6E0 再校验并消费

后续帧更新 9CBF50
  → 满足指定实体标志且战斗时钟达到到期值
  → 9CBE70 清理效果

显式 8150 op=0
  → 82C6E0 → 9C64C0 按效果类型查找并清理
```

**本地到期清理与显式删除包是两条入口。没有抓到 op=0 不能单独证明缺失服务端删除协议。** 本轮尚未追完清理通知 `9C5540 → 93EFB0` 的所有下游，不能声称每次到期必然产生一个 8150 删除上行。

## 3. 8150：添加/删除单一效果

外层 opcode=8071，payload 首 DWORD=8150 (`0x1FD6`)。客户端 `82C6E0` 检查长度 **至少 87B**；当前 Go 实现只接受 **恰好 87B**。这两种约束不能混写。

| 偏移 | 长度/类型 | 含义 | 依据 |
| --- | --- | --- | --- |
| 0 | 4/u32 | 子命令 8150 | 分派与实包 |
| 4 | 8/u64 | 信封发送者 ID | 当前 Go 校验 |
| 12–38 | 27B | 公共信封其余字段 | 见 BattleEventProtocol；部分待解释 |
| 39 (`0x27`) | 8/u64 | 被施加/移除效果的目标实体 ID | 82C736–82C749 查询实体 |
| 47 (`0x2F`) | 8/u64 | 来源实体 ID | 82C74F–82C762 查询实体；传入效果参数 |
| 55 (`0x37`) | 4/u32 | 效果类型 | 82C7A4–82C7AA；删除亦使用此字段 |
| 59 (`0x3B`) | 4/u32 | 效果等级 | 82C794–82C79A；与 GM 配置和实包对应 |
| 63 (`0x3F`) | 4/u32 | 持续毫秒数 | 82C77C–82C782 → 参数+8 → 9C69C0 |
| 67 (`0x43`) | 4 | 附加字段，本样本为0 | 当前 Go 按有限 float32 校验；不能因此确定语义 |
| 71 (`0x47`) | 4 | 附加字段，本样本为0 | 待核验 |
| 75 (`0x4B`) | 4/u32 | 1添加，0删除 | 82C772 与 82C85F 分支 |
| 79 (`0x4F`) | 8B | 本局上下文 | 82C718→817AC0；当前 Go 按 room.ID/Serial 校验 |

处理器还先调用 `985EB0(payload)`；其完整接收门控未在本轮展开。目标实体不存在则退出。添加交给容器 `446E60 → 9C69C0`，成功后触发 `9C5580` 等通知。类型12有特殊准入分支；类型13在显式删除时有额外处理，不能把所有类型视为完全相同。

## 4. 8126：技能效果批量入口

外层 opcode=8071，首 DWORD=8126 (`0x1FBE`)。`82B8D0` 最小长度71B，Go要求恰好71B。

| 偏移 | 类型 | 含义/消费 |
| --- | --- | --- |
| 0–38 | 39B | 公共信封 |
| 39–46 | 8B | 本次实包为10001；本轮未确认其业务角色，不沿用8150布局命名 |
| 47–54 | u64 | 查询来源实体：82B91A→818C70 |
| 55–62 | u64 | 查询目标实体：82B8F6→818C70 |
| 63–66 | u32 | 技能属性查找键：82B98A→A732F0→A71D20 |
| 67–70 | u32 | 传入453E70构造的参数块，再送A02410；确切含义待验证 |

目标通过 `9E7C70` 检查后，处理器按技能对象+0xB0的列表遍历效果条目。每条的前三个DWORD被作为类型、等级、持续值使用，准入通过后构造87B的8150并交 `A3FBB0`。**不是把8126的71B直接改头转成8150，也没有8150式的尾部房间上下文。**

## 5. 持续时间单位与自动到期

### 5.1 毫秒来源已静态确认

1. [65FE70](evidence/0065FE70-clock_constructor.asm) 调 `QueryPerformanceFrequency`，除以 `0xBE83D0` 处的 double **1000.0**，存为计时器除数；同时记录初始性能计数器。
2. [65FEB0](evidence/0065FEB0-clock_now.asm) 调 `QueryPerformanceCounter`，用计数差除以上述除数，截断为整数。因此返回毫秒。
3. [主循环指令](evidence/007EA045-global-clock-write.asm) `7EA045 call 65FEB0; 7EA04A mov [17C8690],eax` 更新全局当前毫秒。
4. [985BD0](evidence/00985BD0-battle_clock.asm) 通过门控后返回 `全局毫秒 - scene+0x80`；不满足条件返回0。
5. [9C69C0](evidence/009C69C0-buff_admit_and_deadline.asm) 在 `9C6B80` 取该战斗时间，`9C6B85` 加上效果持续值。随后 [9CBCD0](evidence/009CBCD0-buff_activate.asm) 把参数块复制到效果对象+0x38，使到期值位于对象+0x40。

因此：正常时钟且没有倍率修正时，duration=3000代表约3秒。`UStateLastCycle` 并非可以直接改写成“秒”的字段。

### 5.2 时钟返回0的明确条件

`985BD0`：

- `scene+0x84 == 0` 且 `4030C0→4031A0 != 2`：返回0。
- `scene+0x80 == 0`：返回0。
- 否则返回 `[17C8690] - scene+0x80`。

[9854E0](evidence/009854E0-battle_clock_baseline.asm) 设置+0x80、+0x88、+0x110时间基准，但本函数**不设置+0x84**。所以“收到开战包/角色可移动”不能独自证明效果计时门已经打开。

### 5.3 自动到期的额外门控

[9CBF50](evidence/009CBF50-buff_update_and_expiry.asm) 的 `9CC023–9CC063`：

1. `room→819120()` 返回的实体非空；它在历史笔记中称host，但本轮只确认调用对象，未重新证明该称呼。
2. 该实体 `44B3F0()` 返回非零；[getter](evidence/0044B3F0-expiry_entity_flag.asm) 实际读取实体+0x1B74。
3. `985BD0()` 返回值以无符号比较达到效果对象+0x40。
4. 调 [9CBE70](evidence/009CBE70-buff_cleanup.asm)，停用效果、清理表现/逻辑、清零参数，进行动作恢复及通知。

以上是静态条件。**本轮未读运行中实体内存，尚不能断言究竟哪一道门导致此次常驻。**

## 8. 离线证据复核

`inspect_buff.py` 是研究用只读脚本，不是服务器或GM运行依赖。需要分析环境中的 `pefile` 和 `capstone`；输入二进制哈希不一致时拒绝套用固定地址。示例（在本目录运行）：

```text
python inspect_buff.py /path/to/gfld.dat evidence --log /path/to/protocol.log --start 2026-09-18T15:28 --end 2026-09-18T15:35
```

脚本仅导出指定函数的反汇编、哈希/计时常量，以及指定时间段的8121/8126/8150。混合日志中的非JSON行会跳过；不会导出登录凭据或修改原文件。更换客户端版本后必须重新确认函数边界与地址，不能修改哈希限制后直接信任旧映射。

## 9. 2026-09-18 20:38 复测与计时修复

当前凌云神腕253030/stage2021已应用duration=1；20:38的8150也为1，不能继续使用15:32的3000样本说明当前配置。两客户端实时读取均为mode=1、scene+84=0、scene+80非零，全局毫秒时钟持续前进，因此985BD0始终返回0。
