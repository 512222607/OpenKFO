# 团队战中立怪物：接入前核查

日期：2026-09-23。目标：团队战保持红蓝对抗，同时加载原版怪物资源，怪物可攻击双方。当前仅完成静态核查，功能尚未实现或部署。

## 当前客户端限制

核对本地 gfxz.dat（SHA256 `1b7c8676e778c7bd47f55184f927338da3cf70c6aa5f0beb59869ea0f0ac9d4e`）和 gfld.dat（SHA256 `98c43be72ac7600b368d4e185d75205376f79e938ea42e4b16ce8f8c4bae827b`），两者的以下消费链相同：

- 8071 子事件 20400、67 字节，由 827AD0 消费。
- 827AEF/827AF4 分别传入 12F8FE8/12F899C 的 RTTI；文件中的类型名称确认为 CPVEBaseMode 和 IBattleMode。
- 827B07 执行动态类型转换，827B12/827B16 检查空指针，失败直接跳至 827B4A 返回。
- 转换成功后才调用模式对象虚函数 +108 创建怪物。因此不能通过只放宽服务器模式检查来实现普通团队战刷怪，更不能只跳过客户端空指针检查。
- 模式21的模板参数是已加载的怪物模板下标，不是道具 ID 或通用模型 ID。模式10使用另一条配置查询链，不能把模式21的下标语义直接套用过去。任意填写一个数不能保证正确加载资源。

关联依据：`protocol/StageWaveProtocol.md`、`protocol/nixiang/pve-actor-lifecycle.asm`、`protocol/nixiang/foster-script-init.asm`、`protocol/nixiang/stage-template-index.asm`。

## 已有服务端复用点

`internal/game/pve_actors.go` 已处理闯关模式房主的怪物创建、移除、身份登记、序号及生命周期。`battle.go` 和可靠事件处理可复用部分动作、移动、伤害转发。当前模式限制具有实际客户端依据，不应直接删除。

## 最小实验及验收

1. 在独立线下客户端验证团队模式下可独立初始化 PVE 怪物模板、实体容器和 AI 更新，保持团队模式对象和原胜负逻辑；未证明兼容前不替换模式类型、不修改虚表强制转型。
2. 先固定一个已有地图、一个原版怪物；核实落点和模板来源。明确谁运行 AI、其他客户端如何只重放同步；控制者离开须有清理或迁移路径。
3. 验证怪物索敌和伤害对红蓝双方一致，双方能伤害怪物；不把怪物死亡写入玩家击杀数或闯关结算。中立阵营取值尚未确认，不猜测魔数。
4. 然后接入服务器受控生成清单、生命周期及房间/场次隔离；全部客户端必须安装相同适配组件。
5. 双窗口实测生成、移动、攻击双方、受伤、死亡、清场和再次开局后，才能声明功能可用。

本次没有向线上或当前游戏进程发送实验生成包，没有修改数据库或客户端二进制。

- 模式10虚表 +108 → 941350，第三个参数经 4D4380 → A62B40 查配置，随后访问模式对象 +98 的容器。
- 模式21虚表 +108 → 93B430，第三个参数经 938E80 查本模式模板，随后访问模式对象 +9C 的容器。
